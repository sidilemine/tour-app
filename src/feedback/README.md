# Private story feedback

`StoryReview` accepts `{ fixture: Fixture, storyIndex: number, onClose: () => void }`. Story indices use `narrationAt`, including walking chapters. Mounting pauses through `setReviewMode(true)`; explicit Save review and resume tour (including Android Back) finalises capture and saves the review before releasing the gate and resuming an active tour. Passive cleanup only releases the UI gate and leaves narration held. Mount only one review at a time.

Three optional integer scores (0–10), heard-before flag and text save immediately into separate `walking-feedback.db` storage through `Store`. Each opening creates a new draft, preserving prior attempts. `presentationSequence` records the order review attempts were opened; it is not proof that every story was heard, or a recording of the complete playback sequence. Story ID/index and tour/version remain separate. History shows recent attempts; JSON export retains all attempts for that tour/version.

Only Record requests microphone access. Expo Audio 57.0.5 records into its private document directory. The actual native URI is durably linked before recording starts. Stop and save verifies a nonempty local file before marking saved; background/close use the same operation. Saving a voice note, permission denial and recording failure never resume narration while Review remains open. Ratings and earlier notes survive recording failures. Audio is excluded from JSON and is not transcribed; an explicit saved copy is separate; JSON strips private URIs and includes only note metadata, ratings and text.

Interrupted in-progress metadata is reconciled when another review opens. Existing bytes are preserved as an interrupted recording whose playability is unverified, without attempting automatic playback. Abrupt process termination can leave unfinalized audio; this does not block ordinary reviews. Saved notes can be played by explicit tap, including from recent history. A separate short-lived player has no lockscreen controls and is stopped/released before another note or recording, on background, close and unmount. Playback never changes the tour hold. Previous reviews are not edited. Audio remains available in private documents for an explicitly authorised later retrieval. Do not uninstall/clear app data if those notes matter.

Validation: real SQLite reopen and atomic-failure tests, score validation, metadata-only export, permission/prepare cancellation races, background finalisation, preservation after file failure, and cancelled/switched/finished voice playback. The pinned Android recorder releases its native MediaRecorder in a finally block on ordinary stop failures; a permission/bridge exception additionally releases the shared recorder, disables further capture in that review, and requires reopening it. The displayed duration poll safely stops using a released recorder. The original phone capture/playback/copy path passed its representative device check; the new headset routing and focus boundary needs its own short check, tracked below. Existing JSON save/share behavior is reused.

API checked against installed Expo source and [official Audio documentation](https://docs.expo.dev/versions/latest/sdk/audio/) on 17 September 2026. Recording permission needs a fresh native build; background recording remains disabled.

Explicit **Save voice copy to folder** now copies one saved note through Android SAF, with unique story/note-ID naming and full byte/MD5 readback. Cancelling or failed saving preserves the original; no automatic sharing occurs. The one clustered phone session verifies the actual provider boundary.

## Android microphone routing and focus

The version-guarded `tools/native/TourRecordingSession.kt` adapter owns transient exclusive focus and temporary Bluetooth communication routing for foreground capture. `recordingInput.ts` waits for an actual MediaRecorder routed-device match before acknowledging recording; a preferred device alone is insufficient. Review shows Headset or Phone microphone and allows an explicit phone fallback. On Android 12+, headset selection requests Nearby devices permission. Native focus loss or route change pauses capture; JS finalises the retained file and never clears the tour hold. Recorder reset releases routing/focus even after stop failure; foreground return never auto-resumes these recorders. See [implementation and physical evidence](../../docs/test-results/M2-recording-input.md).
