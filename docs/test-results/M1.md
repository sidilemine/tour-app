## 13 September — stationary playback and native build correction

Conditions: Pixel 6, Android 17/API 37, ARM64; USB connected; synthetic fixture `synthetic-linear@1`; no location permissions requested, no location tracking or physical route asserted. Sidi confirmed hearing the first clip start and stop when paused. The app saved A at 3.3 s and restored the same offset/manual hold after force-stop; deliberate Resume completed it. All three durable clip files were SHA-256 identical to the repository assets.

A media-key regression exposed a build defect: Android media Pause stopped B, but Play did not release the hold. Temporary native-status inspection showed the generation and command fields absent. Expo had selected its stock precompiled audio module despite our source patch. Earlier build/source inspection did **not** establish that the adapter entered the APK; that earlier conclusion is superseded here.

Correction: `package.json` explicitly builds `expo-audio` from source, as described in [Expo's precompiled-module guide](https://docs.expo.dev/guides/prebuilt-expo-modules/). APK assembly now checks native DEX markers. The playback adapter requires native revision 1 and a valid media generation, so a stock/outdated APK fails explicitly before playback. Source identity now includes package.json. The native patch remains idempotent and version-guarded. No debug instrumentation remains. Two new regression cases reject missing/old native status and accept the required adapter contract.

Both source-built variants passed assembly, signature and native marker checks; Gradle explicitly ran `:expo-audio:compileDebugKotlin` and its release equivalent. After installing the corrected development APK, ADB media Pause produced `manual` hold (B at 5.2 s); media Play released it and B completed. This verifies the Android media-key path, not a physical headset or locked-screen arrival.

The corrected self-contained APK was installed without clearing data. With Metro stopped, USB forwarding removed, Wi-Fi off and active subscription mobile data off, Android reported `Active default network: none`. Cold launch rendered the fixture and retained completed A/B. Manual C playback and media Pause saved 3.4 s. Force-stop and reopen, without any intervening installation or data clear, recovered the same displayed 3.4 s/manual hold. Deliberate in-app Resume completed C offline. Subsequent connectivity settings were restored to their original values and the development build restored. Sidi also confirmed hearing the later B/C clips play, stop when paused and continue on resume in the corrected build.

No walk, background arrival, interruption by a real call/output disconnect, or battery-duration result is implied. The full M1 gate remains open. The fixture on the handset is synthetic and must be replaced with a physically checked recorded/imported route before Start.
