## Connected-device follow-up

The developer welcome was dismissed and Fast Refresh disabled. The initial app and fixture configuration screens rendered without a fatal error. Device inspection exposed literal newline text in the heading and diagnostic separators; JSX string expressions now render actual line breaks, verified in the Android UI hierarchy. Typecheck and lint passed after this display-only correction. Both APKs are rebuilt to include it.

App-scoped development logs include an optional splash-screen class lookup failure and React Native soft exceptions during developer reloads; these did not prevent the observed launch or configuration screen. They are not evidence of successful background audio, location or recovery. No location recording or test tour was started in this installation session.

Both rebuilt APKs passed assembly and signature verification. The development APK checksum is unchanged because its JavaScript comes from Metro; the revised source ID identifies that loaded code. The self-contained APK checksum above changed with its embedded bundle.

The self-contained build installed over the development build without uninstalling and rendered its initial screen after a cold launch with Metro stopped and USB forwarding removed. A subsequent Wi-Fi/mobile-data-off attempt was inconclusive: the phone left the app before the follow-up screen inspection, and the generic mobile-data setting did not confirm the command's effective state. Do not count this as the fully offline acceptance pass. Wi-Fi and mobile data were restored to enabled, matching their initial values. The development build was then restored for the first walk. No progress-recovery or audible-playback claim follows from these launch checks.
